# Аудит Himer65.github.io и PlanktonAI

Дата проверки: 2026-11-07. Проверялись исходники веток `master` сайта и `main` PlanktonAI.

## Итоги

- В исходной шахматной странице `ai/chess/main.js` пользователь мог сделать ход, но ответный ход компьютера отсутствовал. Это функциональный дефект, а не уязвимость.
- Формат контекста в `PlanktonAI/README.md` расходится с `core/data.py`. Реальная подготовка данных использует 7 значений: два one-hot признака стороны, четыре права рокировки в порядке K/Q/k/q и halfmove_clock/50. Описание README упоминает en passant и один скаляр стороны. В браузерной интеграции выбран фактический формат кода подготовки данных.
- `core/data.py` не добавляет en passant в контекст; модель не получает этот признак напрямую. Это ограничение текущей архитектуры/обучения.
- `board_to_tensor` разворачивает FEN в порядок от 8-й горизонтали к 1-й, а `move_to_tensor` кодирует вертикальную координату как rank-1. Браузерный адаптер сохраняет эти разные соглашения, чтобы повторить обучающий pipeline.
- В ноутбуке обучения нет отдельной валидационной выборки: качество и обобщающая способность модели не подтверждаются только приведённым train loss. Заявленная скорость инференса — результат автора для конкретного CPU, а не гарантия для браузеров.
- Зависимости Python в `requirements.txt` не закреплены по версиям. Это риск воспроизводимости сборки, не доказательство уязвимости.
- На сайте используются сторонние CDN-скрипты. Для jQuery, chessboard.js, chess.js и ONNX Runtime в странице нет SRI-хешей; компрометация CDN/поставки может повлиять на клиентский код. Bootstrap CSS на главной странице имеет SRI. В рассмотренном статическом коде не обнаружены API-ключи или серверные секреты.
- В ссылках с `target="_blank"` на странице резюме не указан `rel="noopener noreferrer"`. Современные браузеры обычно подразумевают noopener, но явный атрибут повышает совместимость и ясность.

## Изменения в этой ветке

- Добавлена браузерная интеграция PlanktonAI через ONNX Runtime Web (WASM).
- Добавлены исходные ONNX-файл и внешний файл весов из репозитория PlanktonAI.
- Ход выбирается только среди легальных ходов chess.js; оценка повторяет произведение четырёх выходных вероятностей модели.
- Добавлены сообщения статуса, блокировка пользовательского хода пока отвечает ИИ и перезапуск партии.
- jQuery обновлён до 3.7.1 для использования с chessboard.js 1.0.0.
- Добавлена обработка отсутствующего runtime/ошибки загрузки модели.

## Что не подтверждено

- Не выполнялся полноценный запуск GitHub Pages в реальном браузере.
- Не подтверждены на практике совместимость opset сохранённой ONNX-модели с текущим CDN runtime и автоматическая загрузка внешнего файла весов. Это критический smoke-test перед слиянием PR.
- Не выполнялись динамический DAST, сканирование зависимостей и тесты на разных браузерах/устройствах.
- Не проверялись приватные настройки GitHub Pages, DNS и настройки аккаунта.

## Рекомендации перед слиянием

1. Открыть preview ветки/страницы и проверить загрузку модели в консоли браузера.
2. Сыграть несколько партий: обычные ходы, взятия, рокировка, превращение пешки, шах и конец игры.
3. Если ONNX Runtime отвергает opset модели, переэкспортировать модель с opset, поддерживаемым выбранной версией runtime, затем повторить тесты.
4. Исправить описание Context в README PlanktonAI так, чтобы оно точно совпадало с `core/data.py`; добавить validation/test split.
5. Закрепить версии Python-зависимостей и добавить тесты кодирования FEN/контекста/ходов.
